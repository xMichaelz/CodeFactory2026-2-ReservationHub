# ADR-005 — Organización por dominios de negocio

- **Estado:** Aceptado
- **Fecha:** 2026-09-19
- **Responsable:** Equipo Avanzado CodeF@ctory / ReservaHub

## Contexto
Particionar el monolito por bounded contexts.

## Problema
Se requiere una decisión explícita y trazable para el Sprint 1 de ReservaHub (Caso 14).

## Alternativas consideradas
- Paquetes técnicos globales
- Módulos por dominio
- Feature folders sin dominios

## Criterios de decisión
- Cumplimiento del enunciado del Sprint
- Simplicidad operativa
- Seguridad e integridad de datos
- Testabilidad y mantenibilidad
- Facilidad de ejecución local

## Decisión
Módulos user, provider, servicecatalog, schedule, resource (+ reservation/report futuros)

## Justificación
Refleja el dominio de reservas y facilita ownership por HU.

## Consecuencias positivas
- Alineación con requisitos académicos y técnicos del Sprint
- Claridad para nuevos integrantes del equipo
- Base coherente para sprints posteriores

## Consecuencias negativas
- Algunas capacidades avanzadas quedan fuera de alcance deliberadamente
- Decisiones tempranas pueden requerir evolución (p. ej. auth distribuida)

## Impacto
Afecta diseño de módulos, configuración, seguridad, persistencia y despliegue local.

## Referencias
- Enunciado Sprint 1 ReservaHub / CodeF@ctory Caso 14
- Código implementado en `src/main/java/co/udea/codefactory/reservahub`
- Spring Boot 4.1.1 / Java 25 documentation (sitios oficiales de los productos usados)
